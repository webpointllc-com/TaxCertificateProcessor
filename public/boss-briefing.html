5. Account model — one Postgres on Kamatera

Google = identity · we mint sessions · Allow before feedback

Google supplies: Google user id (sub), email, name. We mint: our own session token (hash stored in Postgres, not an in-memory dict). Every table that holds customer activity has org_id. One company’s searches never leak into another’s. The app asks Allow before we store identity, write feedback, or contact them. No silent capture.

orgs id, name, billing_email, stripe_customer_id, stripe_subscription_id, plan, status, created_at users id, org_id, google_sub, email, name, role (owner|admin|user), created_at sessions id, user_id, token_hash, expires_at, created_at jurisdictions key, state, county, search_url, verified, confidence_notes — the S-PUL registry (URL truth) search_results id, org_id, user_id, query, jurisdiction_key, url, confidence, no_result_reason, created_at feedback id, org_id, user_id, search_result_id, vote (up|down), correction_url, free_text, allow_contact, created_at
